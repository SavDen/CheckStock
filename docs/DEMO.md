# Видеодемонстрация CheckStock

[Видеообзор — 4:58, MP4](demo/checkstock-demo.mp4). [Субтитры SRT](demo/checkstock-demo.srt).

Актуальная версия собрана из кадров работающего приложения, с анимированным курсором, подсветкой кликов и озвучкой ElevenLabs. Приведённый ниже план позволяет воспроизвести сценарий вручную. Исходные материалы первой версии обзора находятся в `demo.json`, `narration.txt` и `demo-frames/`; они не совпадают с актуальной звуковой дорожкой.

## Что открыть заранее

- CheckStock на http://localhost:8000 с исходными 25 единицами.
- `app/service.py`, `app/main.py`, `tests/test_inventory.py`.
- Терминал с завершённым `pytest -q`.

В кадрах обзора также показано завершение FBO/FBS после архивирования исходного склада. Это допустимо для ранее начатых операций. Итоговые остатки от порядка приёмки FBO и архивирования не меняются.

## Короткие ответы на вопросы

**Почему не SQLite?** Поведение транзакционных блокировок проверяется на целевой PostgreSQL. SQLite не воспроизводит PostgreSQL `FOR UPDATE`.

**Почему нет React?** Для четырёх экранов и одного разработчика на день он не требуется. Простой JS снижает объём сборки и зависимостей; серверный стек остаётся заданным.

**Что произойдёт при двойном клике?** Кнопка блокируется; на сервере команда защищена ключом идемпотентности, а повторный переход завершённого движения безопасен сам по себе.

**Что при потере ответа сервера?** Повтор формы с тем же телом использует тот же UUID. Сохранённый ответ возвращается без повторного изменения склада.

**Почему блокируется магазин?** Это простой и проверяемый компромисс для одного магазина. При высокой нагрузке понадобятся блокировки пар SKU/FF и фиксированный порядок их захвата.

**Почему удалённый склад всё ещё виден?** Справочник не может изменить физическое местонахождение товара. Архив оставляет учёт явным и позволяет вывезти остатки.

**Как проверено сохранение количества?** Все приходы = остаток всех ФФ + транзит + завершённые внешние FBO/FBS. Резерв входит в физический остаток; завершённый внутренний перевод повторно не прибавляется.

**Где использован ИИ?** В подготовке кода, документации и тестов. Проверка — реальные складские действия через интерфейс и интеграционные тесты PostgreSQL, включая одновременно исполняемые запросы.
