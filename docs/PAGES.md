# GitHub Pages

Ожидаемый адрес после включения публикации: https://savden.github.io/CheckStock/

## Включение

1. Открыть https://github.com/SavDen/CheckStock/settings/pages под аккаунтом владельца.
2. В Build and deployment выбрать Source: Deploy from a branch.
3. Выбрать ветку main и папку /docs, нажать Save.
4. Дождаться публикации и открыть адрес сайта.

docs/index.html и docs/static уже подготовлены и закоммичены; сборка на сервере не требуется. docs/.nojekyll отключает обработку Jekyll. Пользовательский Actions workflow для публикации не используется. GitHub выполняет служебную публикацию Pages своим встроенным процессом; существующий CI для проверки Python-проекта остаётся отдельным.

## Что работает онлайн

Все экраны существующего интерфейса, приход, резерв/отмена/отправка/доставка FBS, отправка/приёмка FBO, перемещение между ФФ, управление складами и история. Повторные команды не удваивают движения, нехватка проверяется на конкретном ФФ. Серверная версия и браузерная демонстрация имеют отдельные реализации правил.

Это локальные демонстрационные данные каждого посетителя. Нет серверного PostgreSQL, общей базы пользователей или авторизации. Данные хранятся в localStorage под отдельным ключом checkstock:pages-demo:v1. Операции записываются одной заменой сохранённого состояния; при наличии Web Locks API вкладки одного origin сериализуют доступ. Это удобный способ попробовать интерфейс, а не демонстрация серверной конкурентности PostgreSQL.

## Обновление

После изменений в шаблоне или app/static выполнить:

```bash
python scripts/build_pages.py
python scripts/build_pages.py --check
node --test tests/demo-store.test.cjs
```

Затем закоммитить docs/index.html, docs/static и исходники. После push в main Pages обновляется из /docs. Сгенерированные файлы хранятся в Git специально для публикации из ветки без собственного workflow сборки.
