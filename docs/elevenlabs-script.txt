Здравствуйте! Покажу CheckStock — веб-прототип складского учёта. Он помогает менеджеру понять, где находится товар, сколько можно отправить и какие партии уже в пути.

Серверная часть написана на Python с использованием Фаст эй-пи-ай. Данные хранятся в Постгрес. Интерфейс сделан на обычных HTML, CSS и JavaScript. Для небольшого тестового это позволяет обойтись без отдельной сборки фронтенда.

На стартовом экране один магазин, два склада — Север и Юг — и три товара из задания. Всего двадцать пять единиц. Здесь отдельно показаны физический остаток, доступное количество и резерв. Доступно — это физический остаток минус резерв. Товар в пути учитывается отдельно.

Начну с прихода. Добавляю пять органайзеров на Север. Было десять, стало пятнадцать. Изменение сохраняется в базе и появляется в истории.

Теперь резервирую три органайзера под заказ эф-би-эс. Физически на Севере всё ещё пятнадцать, но доступно уже двенадцать. Три единицы остаются на складе, просто их нельзя использовать для другого заказа.

У резерва есть два действия. Отмена освобождает товар. Отправка уменьшает физический остаток и снимает резерв. После отправки на Севере остаётся двенадцать, а три единицы едут к клиенту. Доставку можно подтвердить отдельно.

Проверю нехватку на выбранном складе. Попробую отправить четырнадцать органайзеров с Севера. На Севере доступно двенадцать, на Юге ещё шесть. В сумме товара хватает, но конкретный склад не может отправить четырнадцать.

Система отклоняет операцию и показывает остатки на других складах. При этом ничего не списывается. Автоматически брать недостающее с другого склада нельзя: это скрыло бы реальное местонахождение товара.

Теперь отправлю четыре органайзера по эф-би-о на склад маркетплейса. Они сразу покидают Север и числятся в пути до приёмки. После приёмки поставка завершается. На склад фулфилмента эти единицы обратно не добавляются.

Далее перемещу два органайзера с Севера на Юг. При отправке остаток Севера уменьшается, а остаток Юга пока не меняется. Две единицы находятся в пути между складами. После приёмки на Юге становится восемь органайзеров, на Севере остаётся шесть.

Отдельно покажу управление складами. Новый склад можно добавить и переименовать. Удаление реализовано через архив. Например, на Севере остаются шесть органайзеров и пять контейнеров. Удаление склада не должно уничтожать эти одиннадцать единиц.

Поэтому остатки и история сохраняются. Новые приходы и продажи с архивного склада запрещены. При этом можно вывезти остатки и завершить уже начатые операции. Названия складов в истории сохраняются на момент действия, поэтому переименование не переписывает прошлое.

Теперь о защите учёта. Изменение остатка, статуса движения и запись истории выполняются в одной транзакции. Если возникает ошибка, вся операция откатывается. Ситуации, когда товар списан, а запись о перемещении не появилась, быть не должно.

От одновременного списания защищает блокировка в Постгрес. Пока одна команда меняет остаток, другая ждёт и затем проверяет уже обновлённое количество. Для прототипа с одним магазином выбрана простая блокировка на уровне магазина. При росте нагрузки её можно сделать более точной — по товару и складу.

Отдельная защита предусмотрена для повторных запросов. У каждой команды есть уникальный ключ. Если сервер уже выполнил команду, повтор с тем же ключом вернёт сохранённый результат. Дополнительно проверяется статус движения: повторная приёмка уже завершённой партии не увеличит остаток ещё раз.

Для проверки подготовлены двадцать три интеграционных теста на настоящем Постгрес. Они проверяют обычные складские операции, нехватку, удаление склада с остатками, повторные подтверждения и одновременные запросы.

Инструкция запуска, проверочные сценарии и объяснение решений находятся в README. Локальный запуск проверен. Также подготовлен Docker Compose, но запуск контейнеров на этой машине не проверялся, поскольку Docker здесь не установлен.

ИИ использовался при подготовке кода, тестов и документации. Результат проверен автоматическими тестами и складскими сценариями через интерфейс. Границы прототипа обозначены явно: один магазин, целые количества, без авторизации и интеграции с маркетплейсом. Основной акцент — на понятном и корректном учёте товара.
